# iOS build on GitHub Actions

`.github/workflows/ios-build.yml` builds the Kyco Flutter app for iOS on a
**macOS runner** (iOS binaries cannot be built on Linux). It runs on every push
to `master`/`main` that touches `lib/`, `ios/`, `test/`, or the pubspec, on PRs,
and on manual **Run workflow** (Actions tab → *iOS build* → Run workflow, with an
optional `api_base`).

Pipeline: `flutter pub get` → `flutter analyze` → `flutter test` → build iOS.

## Two modes (chosen automatically)

| | When | Output artifact | Needs |
|---|---|---|---|
| **Unsigned** (default) | no signing secrets set | `kyco-mobile-ios-unsigned` (`.ipa`) | nothing — works out of the box |
| **Signed** | all signing secrets set | `kyco-mobile-ios-signed` (`.ipa`) | Apple Developer account + secrets below |

The **unsigned** IPA proves the iOS build compiles and produces an artifact you
can resign later (AltStore / a resigning tool / a personal team). It is **not**
directly installable and **cannot** go to TestFlight — that needs the signed mode.

## Activate it (repo has no GitHub remote yet)

```bash
# create an empty repo on GitHub first (gh or the web UI), then:
cd apps/kyco-mobile
git remote add origin git@github.com:<you>/kyco-mobile.git
git push -u origin master
```
Actions runs on the first push. macOS runner minutes cost 10× Linux on private
repos — keep this repo public, or watch the minutes budget.

## Enable signed / TestFlight builds

Add these under **Settings → Secrets and variables → Actions** (all base64 so no
raw files touch git). Once all of `IOS_CERTIFICATE_BASE64`,
`IOS_PROVISIONING_PROFILE_BASE64`, `IOS_EXPORT_OPTIONS_PLIST` exist, the next run
switches to the signed path.

| Secret | What it is | How to get it |
|---|---|---|
| `IOS_CERTIFICATE_BASE64` | Apple **Distribution** cert as `.p12`, base64 | Xcode/Keychain → export your *Apple Distribution* identity as `.p12` → `base64 -i cert.p12 \| pbcopy` |
| `IOS_CERTIFICATE_PASSWORD` | password you set when exporting the `.p12` | — |
| `IOS_PROVISIONING_PROFILE_BASE64` | matching `.mobileprovision`, base64 | developer.apple.com → Profiles (App Store or Ad Hoc for `com.kyco.kycoMobile`) → download → `base64 -i profile.mobileprovision \| pbcopy` |
| `IOS_KEYCHAIN_PASSWORD` | any throwaway string | make one up |
| `IOS_EXPORT_OPTIONS_PLIST` | `ExportOptions.plist`, base64 | template below → `base64 -i ExportOptions.plist \| pbcopy` |

`ExportOptions.plist` (set `method` = `app-store` for TestFlight, `ad-hoc` for
device testing; `teamID` = your 10-char Apple Team ID):

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
  <key>method</key><string>app-store</string>
  <key>teamID</key><string>XXXXXXXXXX</string>
  <key>signingStyle</key><string>manual</string>
  <key>uploadBitcode</key><false/>
  <key>uploadSymbols</key><true/>
</dict>
</plist>
```

The bundle id is **`com.kyco.kycoMobile`** — the cert, profile, and App Store
Connect app record must all match it.

## Upload the signed IPA to TestFlight (optional next step)

Add a final step after *Build signed IPA* using an App Store Connect **API key**
(`APP_STORE_CONNECT_KEY_ID` / `_ISSUER_ID` / `_KEY_BASE64` secrets) and
`xcrun altool --upload-app` or `apple-actions/upload-testflight-build`. Ask and
I'll wire it in.

## Notes
- Flutter is pinned to **3.47.2** to match local dev — bump it here and in the
  team's toolchain together.
- The app targets **iOS 15.0** (`ios/Runner.xcodeproj`), talks to the backend
  over HTTPS (`https://kyco.vn/api/v1`) so no ATS exception is needed; override
  per build with the `api_base` workflow input or `--dart-define=API_BASE=`.
- CocoaPods `Podfile`/`Pods/` are generated by `flutter build` on the runner —
  they are intentionally not committed.
